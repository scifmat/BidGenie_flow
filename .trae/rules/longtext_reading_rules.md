# 长文本读取规则

## 规则描述

- 当需要读取的文本内容长度超过 **2000行** 或文件大小超过 **500KB** 时，需要触发该规则
- 当读取文本出现 **超时、阻塞、异常** 时，需要触发该规则
- 该规则适用于所有文件读取操作（.md、.txt、.json 等文本格式）

## 规则决策与执行

### 第一步：判断是否需要分段读取

在调用 Read 工具前，先评估文件规模：

| 判断条件 | 阈值 | 是否需要分段 |
|----------|------|:-----------:|
| 文件行数（预估） | > 2000 行 | ✅ 需要 |
| 文件大小 | > 500KB | ✅ 需要 |
| 文件行数（预估） | ≤ 2000 行 | ❌ 不需要 |
| 文件大小 | ≤ 500KB | ❌ 不需要 |

**行数预估方法**：通过 Shell 命令 `wc -l filename` 快速获取（无需全量读取）

### 第二步：分段读取策略

如果需要分段读取，根据文本内容的 **逻辑结构** 进行分段，优先按以下策略执行：

#### 策略一：按 Markdown 标题层级分割（推荐）

适用于结构化文档（如招标文件、技术方案等）：

```markdown
# 第一部分  → 第一段：1-600行
## 第一节    → 第一段内继续分割
## 第二节

# 第二部分  → 第二段：601-1200行
## 第一节
## 第二节

# 第三部分  → 第三段：1201-1800行
...
```

**执行步骤**：
1. 先读取前 200 行，识别标题层级结构
2. 根据标题分布，计算每段的行数范围（每段 ≤ 1900 行）
3. 按计算的范围分段调用 Read 工具

#### 策略二：按固定行数分割（兜底策略）

适用于非结构化文档或标题不明确的情况：

- 第一段：1-1900 行
- 第二段：1901-3800 行
- 第三段：3801-5700 行
- ... 以此类推，最后一段取剩余所有行

#### 策略三：按章节/段落标记分割

适用于有明确章节标记的文档（如 PDF 转换文档）：

- 查找章节标记：`第X章`、`Chapter X`、`Section X`、`一、`、`二、` 等
- 以章节边界作为分段点

### 第三步：分段读取执行

1. **调用 Read 工具**：每段读取不超过 **1900 行**，设置合理的 `offset` 和 `limit`
2. **顺序读取**：从第一段开始，逐段读取，每段读取完成后再读取下一段
3. **记录进度**：读取每段后记录当前已读取的行数范围，便于后续引用
4. **上下文衔接**：每段的最后 50 行与下一段的前 50 行重叠，确保章节衔接不遗漏

### 第四步：内容整合

分段读取完成后，按顺序整合所有段落内容，确保：
- 内容完整、无遗漏
- 章节衔接自然
- 格式保持一致

## 失败处理

### 读取失败重试机制

当读取文本内容失败时，执行以下重试流程：

```
第一次读取失败
    ↓
等待 2 秒后重试（第二次）
    ↓
若仍失败，等待 5 秒后重试（第三次）
    ↓
若仍失败，记录失败信息并反馈给用户
```

**重试限制**：最多重试 **3 次**，每次重试间隔递增（2秒 → 5秒）

### 失败信息记录

记录内容包括：
- 文件路径
- 失败原因（超时/异常/其他）
- 失败时尝试读取的行数范围
- 重试次数及结果
- 建议的解决方案

### 异常情况处理

| 异常类型 | 处理方式 |
|----------|----------|
| 文件不存在 | 提示用户确认文件路径 |
| 权限不足 | 提示用户检查文件权限 |
| 编码错误 | 尝试 UTF-8、GBK、GB2312 等编码重试 |
| 网络超时 | 增加超时时间，分段读取减小单次读取量 |
| 文件损坏 | 提示用户检查文件完整性 |

## 最佳实践

### 文件预处理

- 对于已知超长文件，先通过 `wc -l` 命令获取精确行数
- 如果文件格式支持，考虑使用命令行工具（如 `head`、`sed`）预览文件结构

### 内存管理

- 分段读取时，每段读取完成后立即处理（提取关键信息/分析），避免一次性加载全部内容到内存
- 对于超长文件（>10000行），考虑边读取边处理，不保存完整副本

### 进度反馈

- 读取每段后输出进度提示，如：`已读取 1-1900 行（共约 5000 行，进度 38%）`
- 让用户了解读取进度，提高交互体验

### 缓存策略

- 对于需要多次读取的同一文件，可缓存已读取的段落内容，避免重复读取
- 缓存有效期为当前会话，会话结束后自动清除

## 示例

### 示例1：结构化 Markdown 文件（约 4500 行）

```bash
# 先获取总行数
wc -l document.md
# 输出：4523 document.md

# 按标题分段读取
Read offset=1, limit=1500    # 第一部分
Read offset=1450, limit=1500 # 第二部分（重叠50行）
Read offset=2950, limit=1600 # 第三部分
```

### 示例2：非结构化文本文件（约 3200 行）

```bash
# 按固定行数分段读取
Read offset=1, limit=1900    # 第一段
Read offset=1901, limit=1900 # 第二段（最后一段自动截断）
```

### 示例3：读取失败重试

```bash
# 第一次读取失败
Read offset=1, limit=2000
# 结果：超时

# 等待 2 秒后第二次读取
sleep 2
Read offset=1, limit=1500
# 结果：成功读取第一段

# 继续读取第二段
Read offset=1501, limit=1500
```
