# 去AI味写作规则

本规则文档用于指导 writer-agent 撰写技术方案正文时消除AI写作痕迹，使内容更具人文感和真实感。本规则与 writing_rules.md 配合使用，适用于投标技术方案这类正式商务文档场景。

**核心原则**：
    - 保持专业严谨的同时，消除模板化句式、空洞套话和机械过渡，使文字更贴近人类专家的真实表达。
    - 减少甚至避免正文的[开头/结尾]的`总结式`段落，保持内容的连贯性和真实感。
    - 保持句式的节奏和变化，长短句交错使用，避免使用相同的句式。

## 一、禁用的AI高频词和过渡词

### 1.1 禁用的过渡词

以下词汇是AI写作的典型特征，禁止使用：

| 类别 | 禁用词汇 | 替代方案 |
|------|---------|---------|
| 总结类 | 综上所述、总而言之、总的来说、一言以蔽之、概而言之 | 简单来说、具体来看、实践中、事实上 |
| 递进类 | 此外、与此同时、进一步而言、尤为重要的是、值得注意的是 | 而且、更关键的是、在这一点上、另外 |
| 转折类 | 然而、尽管如此、不可否认的是、不可避免的是 | 但、不过、实际上、客观来看 |
| 强调类 | 至关重要、不可或缺、必不可少、举足轻重 | 关键、重要、必须、核心 |
| 开头类 | 在新时代背景下、随着XXX的快速发展、当前XXX领域 | 如今、目前、当前、近年来 |
| 引用类 | 专家认为、行业报告显示、相关研究表明、据统计 | 具体数据表明、实践经验证明、我们认为 |

### 1.2 禁用的套话短语

禁止使用以下空洞的AI套话：

- "作为XXX的体现"、"凸显了XXX的重要性"、"具有重要意义"
- "为了XXX的目的"、"在XXX的基础上"、"从XXX角度出发"
- "实现XXX的目标"、"确保XXX的质量"、"保障XXX的安全"（无具体措施支撑时）
- "赋能"、"底层逻辑"、"闭环"、"抓手"、"落地"、"打通"（非技术场景滥用）

### 1.3 禁用的结尾升华句式

禁止使用以下强行升华的结尾方式：

- "展望未来，XXX将迎来新的机遇"
- "相信通过XXX，一定能够XXX"
- "综上所述，XXX具有广阔的发展前景"
- "总之，XXX是一项具有重要意义的举措"

## 二、句式节奏要求

### 2.1 长短句交错

AI写作倾向于使用均匀长度的句子，显得机械。要求：

- **禁止连续使用相同长度的句子**
- 每段中至少包含1个短句（5-10字）和1个长句（30字以上）
- 合理使用断句、倒装、省略等方式打破规整感

**正确示例**：
```markdown
本项目采用分布式架构。核心节点部署在主数据中心，边缘节点覆盖各运维站点，实现数据就近处理和实时响应。

这样的设计，既保证了系统的可靠性，又提升了响应速度。
```

**错误示例**（句式均匀，AI味重）：
```markdown
本项目采用分布式架构，核心节点部署在主数据中心，边缘节点覆盖各运维站点，实现数据就近处理和实时响应，既保证了系统的可靠性，又提升了响应速度。
```

### 2.2 主动语态优先

- 优先使用主动语态，避免过度使用被动语态
- AI倾向于使用"XXX可以被实现"，改为"我们可以实现XXX"或直接陈述

**正确示例**：
```markdown
运维团队每日巡检设备运行状态，及时发现并处理潜在故障。
```

**错误示例**：
```markdown
设备运行状态被运维团队每日巡检，潜在故障被及时发现并处理。
```

### 2.3 减少修饰词堆砌

- 避免连续使用多个形容词或副词修饰同一个名词
- 删除冗余的修饰词，保留核心信息

**正确示例**：
```markdown
建立完善的应急预案体系，覆盖各类极端天气场景。
```

**错误示例**：
```markdown
建立一套科学合理、全面系统、切实可行的应急预案体系，全面覆盖各类复杂多变的极端天气场景。
```

## 三、内容表达要求

### 3.1 拒绝模板化结构

AI写作倾向于使用固定的"总分总"结构，要求：

- **禁止机械套用"背景-现状-问题-对策"的固定模板**
- 根据实际内容需要组织段落结构，允许灵活安排
- 避免每段都以"首先、其次、再次"开头

### 3.2 具体案例和数据支撑

- 每个核心观点必须有具体数据、案例或措施支撑
- 禁止空泛论述，避免"我们将采取有效措施"这类无实质内容的表述

**正确示例**：
```markdown
针对冬季冰雪天气，我们制定了三级响应机制：当气温低于-5℃且降雪量超过5mm时启动二级响应，运维人员在2小时内到达现场进行除雪作业。去年冬季共启动响应12次，平均响应时间1.8小时，有效保障了道路通行安全。
```

**错误示例**：
```markdown
针对冬季冰雪天气，我们制定了完善的响应机制，能够及时有效地处理各类冰雪灾害，保障道路通行安全。
```

### 3.3 平实自然的开头结尾

- 开头直接切入主题，避免冗长的背景铺垫
- 结尾根据内容自然收尾，不强行升华

**正确示例**：
```markdown
#### 应急响应机制

本项目建立了三级应急响应机制，根据灾害等级和影响范围启动相应级别的响应措施。

一级响应适用于重大灾害事件，由项目总指挥统一调度；二级响应适用于较大灾害，由区域负责人协调处理；三级响应适用于一般灾害，由现场运维人员直接处理。

实际运行中，这套机制已多次成功应对各类突发事件，平均响应时间控制在2小时以内。
```

**错误示例**（模板化开头结尾）：
```markdown
#### 应急响应机制

随着极端天气事件的日益频繁，建立科学有效的应急响应机制显得尤为重要。本项目充分考虑了各类灾害场景，建立了完善的三级应急响应机制。

首先是一级响应，适用于重大灾害事件；其次是二级响应，适用于较大灾害；最后是三级响应，适用于一般灾害。

综上所述，本项目的应急响应机制具有科学性、系统性和实用性，能够有效保障项目的安全稳定运行，具有重要的现实意义。
```

### 3.4 适度保留"不完美"

真人写作会有轻微重复、临时插话、突然跳转等自然特征：

- 允许适度的语义重复（同一观点从不同角度阐述）
- 允许使用"也就是说"、"换个角度看"等过渡
- 允许自问自答的表达形式

**示例**：
```markdown
为什么要建立这样的巡检机制？因为设备故障往往有一个发展过程，早期发现异常可以避免故障扩大。所以我们设定了每日三次的巡检频率，确保及时捕捉设备运行状态的变化。
```

## 四、排比和对仗限制

### 4.1 禁止排比堆砌

- 禁止连续使用三个及以上结构相同的排比句
- 禁止使用"一是...二是...三是..."的机械列举方式

**正确示例**：
```markdown
服务保障措施包括三个方面：定期巡检、实时监控和快速响应。定期巡检确保及时发现潜在问题，实时监控实现异常情况的自动预警，快速响应保证故障在最短时间内得到处理。
```

**错误示例**：
```markdown
服务保障措施包括三个方面：一是定期巡检，确保及时发现潜在问题；二是实时监控，实现异常情况的自动预警；三是快速响应，保证故障在最短时间内得到处理。这三项措施相互配合、相互支撑、相互补充，共同构成了完善的服务保障体系。
```

### 4.2 禁止过度对仗

- 避免为了对仗工整而牺牲内容的准确性和自然性
- 禁止使用"安全第一、质量为本、服务至上"这类四字短语堆砌

## 五、术语和表述要求

### 5.1 术语使用自然

- 术语首次出现时简洁说明，避免冗长的定义
- 后续使用保持一致，不刻意替换同义词

**正确示例**：
```markdown
BIM（建筑信息模型）技术用于设施的全生命周期管理。本项目中，BIM模型将作为运维管理的核心数据基础。
```

**错误示例**：
```markdown
建筑信息模型（Building Information Modeling，简称BIM）是一种数字化代表设施物理和功能特性的信息模型，通过对设施全生命周期数据的集成与管理，实现设施的可视化、协同化和精细化管理。在本项目中，我们将运用这一先进的数字化建模技术作为运维管理的核心数据基础。
```

### 5.2 避免过度书面化

- 适当使用口语化表达，但保持专业严谨
- 禁止使用过于生僻或晦涩的词汇

## 六、去AI味自查清单

### 6.1 词汇检查
- [ ] 未使用"综上所述"、"总而言之"、"与此同时"等禁用过渡词
- [ ] 未使用"赋能"、"底层逻辑"、"闭环"等空洞套话
- [ ] 未使用"至关重要"、"不可或缺"等夸张强调词

### 6.2 句式检查
- [ ] 段落中长短句交错，没有连续相同长度的句子
- [ ] 主动语态优先，没有过度使用被动语态
- [ ] 没有修饰词堆砌，表达简洁

### 6.3 结构检查
- [ ] 没有机械套用"背景-现状-问题-对策"模板
- [ ] 没有使用"首先、其次、再次"的机械列举
- [ ] 结尾没有强行升华，自然收尾

### 6.4 内容检查
- [ ] 每个核心观点都有具体数据或案例支撑
- [ ] 没有空泛论述，避免"有效措施"等无实质内容的表述
- [ ] 术语使用自然，没有过度冗长的定义

### 6.5 风格检查
- [ ] 没有排比堆砌（连续三个及以上相同结构）
- [ ] 没有过度对仗的四字短语堆砌
- [ ] 适当保留自然表达，不追求过于完美的规整感
