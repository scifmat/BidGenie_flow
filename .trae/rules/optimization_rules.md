# 内容优化规则

本规则文档用于指导 optimizer-agent 优化技术方案正文，必须严格遵循。

## 一、分级处理规则

### 1.1 严重问题处理（P1）

**处理方式**：重新生成或大幅修改对应内容

**严重问题类型与处理策略**：

| 严重问题类型 | 处理策略 | 注意事项 |
|-------------|----------|----------|
| 缺失要点 ≥ 2 个 | 补充缺失要点的完整论述，每个要点至少 200 字 | 参考 content_plan 和评审标准 |
| 未响应评分点 ≥ 1 个 | 增加评分点响应内容，详细论述 | 高权重评分点需更详细响应 |
| 逻辑漏洞 | 修正逻辑错误，补充论证步骤 | 确保前后逻辑一致 |
| 技术参数错误 | 修正技术参数，引用正确数据 | 数据来源可追溯 |
| 技术方案不可行 | 调整方案，确保可行性 | 必要时重新设计方案 |

**严重问题优化要求**：
- 必须修复，不允许跳过
- 修复后内容必须充分响应评审标准
- 重写内容必须遵循 anti_ai_writing_rules.md

### 1.2 一般问题处理（P2）

**处理方式**：补充内容、修正图表、调整字数

**一般问题类型与处理策略**：

| 一般问题类型 | 处理策略 | 注意事项 |
|-------------|----------|----------|
| 缺失要点 = 1 个 | 补充该要点的论述，至少 150 字 | 与上下文衔接 |
| 响应不充分 | 扩展论述深度，增加论证细节 | 引用具体数据和案例 |
| 内容重复率 > 20% | 删除重复内容，整合表述 | 保持内容完整性 |
| 标准规范引用错误 | 修正引用，确保准确 | 引用最新版本标准 |
| 字数不足（偏差 > 15%） | 补充内容，扩展论述 | 只下限不限上限 |
| Mermaid 语法错误 | 修正语法，确保图表可渲染 | 测试语法正确性 |
| 图表数量不匹配 | 补充缺失图表或删除多余图表 | 同步更新图题 |
| 标题格式错误 | 修正标题，去除数字编号 | 仅使用 Markdown 层级符号 |

**一般问题优化要求**：
- 建议修复，优先处理影响评分的问题
- 修复后不影响其他已合格内容

### 1.3 建议性问题处理（P3）

**处理方式**：局部微调、语言润色、格式修正

**建议性问题类型与处理策略**：

| 建议性问题类型 | 处理策略 | 注意事项 |
|----------------|----------|----------|
| 轻微遗漏（覆盖率 60%-80%） | 补充遗漏要点的简要论述 | 至少 100 字 |
| 语言风格不一致 | 统一术语和语言风格 | 全文一致性 |
| 表述不够专业 | 替换口语化表达为专业术语 | 使用行业通用术语 |
| 图题格式错误 | 修正图题格式 | `*图 <层级编号>-<图表序号> <图题名称>*` |
| 段落格式不规范 | 调整段落空行 | 段落之间空一行分隔 |

**建议性问题优化要求**：
- 视情况修复，不影响整体流程
- 修复时避免破坏已合格内容

## 二、字数控制规则（与阶段五、六一致，只下限不限上限）

### 2.1 字数偏差判定

| 字数情况 | 判定 | 处理方式 |
|----------|------|----------|
| 实际字数 ≥ 计划字数 | 合格 | 不限制，不删减 |
| 计划字数 × 85% ≤ 实际字数 < 计划字数 | 合格 | 仅记录 |
| 计划字数 × 50% ≤ 实际字数 < 计划字数 × 85% | 一般问题 | 补充内容 |
| 实际字数 < 计划字数 × 50% | 严重问题 | 大幅补充或重写 |

### 2.2 字数调整策略

- **字数不足**：补充内容，扩展论述深度
  - 优先补充 content_plan 中已列但未充分展开的要点
  - 引用具体数据、案例、技术规范
  - 增加论证细节，避免空泛论述
- **字数超标**：仅记录，不限制（鼓励充分论述，不删减）

### 2.3 字数统计口径（与阶段五、六一致）

| 统计项 | 是否计入字数 |
|--------|-------------|
| 正文段落文字 | 是 |
| 标题文字 | 否 |
| 图表代码块 | 否 |
| 图题文字 | 否 |
| 表格内容 | 是 |
| 列表内容 | 是 |
| 引用内容 | 是 |

## 三、格式规范规则

### 3.1 标题格式（优化后必须符合）
- 所有标题**不添加数字编号**
- 标题层级不得超过大纲节点层级一级
- 标题层级连续，不跳级
- 标题后不添加标点符号

### 3.2 正文排版（优化后必须符合）
- 段落首行缩进2字符（使用全角空格）
- 段落之间空一行分隔
- 使用中文标点符号
- 术语首次出现时注明定义或全称

### 3.3 图表规范（优化后必须符合）
- Mermaid 代码块前添加 chart_type 注释
- Mermaid 代码块后添加图题引用标记
- 图题格式：`*图 <层级编号>-<图表序号> <图题名称>*`
- 图表就近放置，不跨章节

## 四、反 AI 味规则（重写内容时必须遵循）

### 4.1 避免 AI 痕迹

- **避免模板化表述**：不使用"首先...其次...最后..."、"综上所述"、"总而言之"等模板化连接词
- **避免空泛论述**：使用具体数据和案例，避免"具有重要意义"、"起到关键作用"等空泛表述
- **避免过度对仗**：段落长度有变化，避免均匀分段和过度排比
- **保持专业术语一致性**：同一术语在全文中保持一致

### 4.2 增强人文感

- 使用具体的数据、案例、技术规范引用
- 段落长度自然变化，避免均匀分段
- 论证过程有逻辑层次，避免平铺直叙
- 适当使用专业术语，但避免堆砌

## 五、优化执行规则

### 5.1 优化优先级
1. 严重问题（必须修复）
2. 一般问题（建议修复）
3. 建议性问题（视情况修复）

### 5.2 优化范围控制
- **精准修复**：仅修改有问题的段落，不破坏已合格的内容
- **保持上下文衔接**：修改后内容必须与上下文段落逻辑衔接
- **避免过度优化**：不修改未提出问题的内容

### 5.3 优化后自检
- [ ] 所有严重问题已处理
- [ ] 所有一般问题已处理
- [ ] 建议性问题视情况处理
- [ ] 格式自查通过（参考 writing_rules.md）
- [ ] 重写内容无 AI 痕迹（参考 anti_ai_writing_rules.md）
- [ ] 字数符合要求（实际字数 ≥ 计划字数 × 85%）
- [ ] 内容覆盖 content_plan 中的所有要点

## 六、用户反馈处理规则（仅 round > 1 时）

### 6.1 用户反馈优先级
- 用户反馈优先级高于审查报告
- 如用户反馈与审查报告冲突，以用户反馈为准

### 6.2 用户反馈类型与处理

| 用户反馈类型 | 处理方式 |
|-------------|----------|
| 整体修改意见 | 调整全文风格、统一表述 |
| 具体章节修改 | 针对指定章节优化 |
| 新增内容要求 | 补充新内容到指定位置 |
| 删除内容要求 | 删除指定内容，调整上下文衔接 |
| 结构调整要求 | 报告主控 Agent，由 outline-agent 处理 |

### 6.3 用户反馈记录
- 用户反馈必须记录到 metadata.json 的 user_feedback_history 数组
- 每轮反馈记录：`{round, feedback_content, processed_nodes, timestamp}`

### 7.1 内容检查
- [ ] 所有严重问题已修复
- [ ] 所有一般问题已修复（或已记录未修复原因）

- [ ] 评分点已充分响应
- [ ] 无逻辑漏洞
- [ ] 无技术参数错误

### 7.2 格式检查

- [ ] 段落格式符合规范（空行分隔）
- [ ] 图表格式符合规范（Mermaid 语法、图题格式）
- [ ] 表格格式符合规范（标题位置、格式）
- [ ] 标点符号使用中文标点

### 7.3 字数检查
- [ ] 实际字数 ≥ 计划字数 × 85%
- [ ] 字数超标仅记录，不删减

### 7.4 反 AI 味检查
- [ ] 无模板化表述
- [ ] 无空泛论述
- [ ] 段落长度有变化
- [ ] 使用具体数据和案例

### 7.5 输出检查
- [ ] 文件已覆盖写入原路径
- [ ] 文件内容完整，无截断
- [ ] 文件编码为 UTF-8
